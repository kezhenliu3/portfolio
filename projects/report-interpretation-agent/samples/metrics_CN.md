# 指标表 — 检索链路与延迟分解

本页数字分**两层**，严格区分：

- **实测 / 文档有据** — 项目开发期间的开发测试记录或设计文档记载值。
- **生产上报口径** — 生产运营侧报告值。**仓库内不公开压测脚本，仅作方向性参考。** 单独列在最后一张表，不用于正文设计性论断。

## 1. 延迟分解（实测）

| 路径 | 延迟 | 说明 |
|---|---|---|
| 规则命中 NLU（FlashText 短路） | ~380 ms | 该路径不调用大模型 |
| LLM 兜底 NLU | ~1.2 s | 规则未命中时 |
| 槽位路由，LRU 缓存前 | ~1200 ms | 提取器每轮请求重建 |
| 槽位路由，LRU 缓存后 | ~600 ms | 提取器按报告类型缓存（−50%） |
| Milvus 查询，热集合 | ~120 ms | 集合已加载进内存 |
| Milvus 查询，冷集合 | ~250 ms | 首次访问需加载集合 |
| 冷启动（首请求，懒加载单例） | 3–5 s | 一次性重资源初始化 |
| 温路径（启动后） | ~100 ms | 配置常驻内存 |

*以上为开发测试中的点位测量，非公开基准套件。结论看结构：规则短路比 LLM 路径快一个数量级，缓存使槽位路由减半，热集合快约 2 倍。*

## 2. 检索与架构数字

| 机制 | 值 |
|---|---|
| RAG 漏斗宽度 | 15 条（RRF 融合后）→ 交叉编码器重排后 **Top-5** |
| RRF 融合 | `1/(rank+k)` 打分，内容 sha256 去重 |
| 实体链接（指标轨） | 在线候选召回 + 余弦二次校验，阈值 0.8 |
| 实体链接（章节轨） | 启动预计算章节库，余弦匹配，阈值 0.6 |
| KG 子图净化 | 三段去重（按 kg-id → 按 kg-id+节点类型 → 按类型分流格式化），证据裁剪为每回答 Top-3 |
| DB 召回 | 章节精确匹配优先，章节级兜底 |
| 安全护栏 | 违禁词分词后 O(1) 反向索引查表 |
| 会话隐私 | 对话历史存 Redis、TTL 24 小时，不落盘 |
| 并发 | 三路检索源 `asyncio.gather` 并发调度；uvicorn 4 workers、并发上限 1000 |
| 连接池 | 数据库 30 + 70 溢出；图数据库 50 |
